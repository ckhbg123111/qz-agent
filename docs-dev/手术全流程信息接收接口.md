# 手术全流程信息接收接口

## 1. 设计说明

本文档基于现有 `QzHpInterfaceController` 的接口风格进行扩展设计，面向住院手术全流程事件接收场景，覆盖以下 4 个业务节点：

1. 办理入院
2. 手术确认
3. 手术完成单
4. 办理出院

设计原则如下：

- 返回结构沿用现有项目风格，统一返回 `Result<Boolean>`，仅表达成功/失败。
- 患者基本信息字段命名尽量复用现有 `QzHp*Request` 风格，如 `patientId`、`patientName`、`gender`、`age`。
- 结合国内 HIS、ADT、手术麻醉系统常见字段设计入参，确保字段语义符合住院、手术排程、术后记录、出院记录等医疗场景。
- 诊断字段优先使用 `ICD-10`，手术/操作字段优先使用 `ICD-9-CM3` 或院内手术操作编码。
- 时间字段统一建议使用 ISO-8601 格式：`yyyy-MM-dd'T'HH:mm:ssXXX`。
- 除必要备注外，优先使用“编码 + 名称”双字段，避免关键业务字段仅传自由文本。

## 2. 行业调研结论

结合国内医院 HIS、ADT、手术麻醉系统、病案首页规范以及住院病历书写习惯，手术全流程接口设计通常遵循以下规律：

- 入院事件重点关注患者主索引、住院号、病案号、科室、病区、床位、入院时间、入院诊断、主治医生、住院状态。
- 手术确认事件重点关注手术申请单号/手术单号、拟手术与确认手术、手术级别、手术部位、手术间、台次、术者、助手、麻醉医生、麻醉方式、计划开始时间。
- 手术完成单重点关注术中诊断、实际手术名称及编码、实际开始/结束时间、麻醉实施情况、ASA 分级、切口等级、切口愈合等级、出血量、输血量、并发症、标本送检、术后去向。
- 出院事件重点关注出院时间、出院科室、出院诊断、出院情况、转归、住院天数、出院医嘱、随访建议。
- 医疗系统对接通常要求事件具备幂等标识和链路追踪字段，如 `eventId`、`traceId`。
- 跨院区或多系统对接时，通常要求携带 `hospitalId`、`orgCode`、`sourceSystem` 等来源标识。

## 3. 接口总体约定

### 3.1 服务信息

- 服务前缀：`/api/b2b/qz/surgery`
- 请求方式：`POST`
- 数据格式：`application/json`
- 字符集：`UTF-8`
- 返回格式：统一 `Result<Boolean>`

### 3.2 通用返回结构

成功示例：

```json
{
  "code": 200,
  "message": "success",
  "data": true
}
```

失败示例：

```json
{
  "code": 400,
  "message": "参数错误",
  "data": null
}
```

字段说明：

- `code`：状态码，`200` 表示成功。
- `message`：状态描述。
- `data`：业务结果，成功时返回 `true`。

### 3.3 命名与数据规范

- `patientId`：患者主索引，建议传 HIS 患者唯一标识。
- `visitId`：本次住院/就诊唯一标识。
- `visitNo`：就诊号或住院号，允许与医院现有主索引习惯保持一致。
- `caseNo`：病案号。
- `eventId`：事件唯一标识，建议作为幂等键。
- `traceId`：链路追踪号，便于日志排查。
- `eventTime`：事件发生时间。
- `hospitalId`：平台侧医院唯一标识。
- `orgCode`：医疗机构编码。
- `sourceSystem`：来源系统，如 `HIS`、`EMR`、`ORMS`、`ANESTHESIA`。
- `encounterType`：就诊类型，住院手术场景建议固定为 `INPATIENT`。

### 3.4 推荐枚举值

#### 性别 `gender`

- `男`
- `女`
- `未知`

#### 就诊类型 `encounterType`

- `INPATIENT`
- `OUTPATIENT`
- `EMERGENCY`

#### 入院类型 `admissionType`

- `NORMAL`
- `EMERGENCY`
- `TRANSFER_IN`
- `DAY_SURGERY`

#### 手术状态 `surgeryStatus`

- `SCHEDULED`
- `CONFIRMED`
- `IN_PROGRESS`
- `COMPLETED`
- `CANCELLED`

#### 手术级别 `operationLevel`

- `1`
- `2`
- `3`
- `4`

#### 麻醉方式 `anesthesiaMethodCode`

建议传国家或院内麻醉方式编码，同时携带中文名称，例如：

- `GENERAL` / 全身麻醉
- `SPINAL` / 椎管内麻醉
- `EPIDURAL` / 硬膜外麻醉
- `LOCAL` / 局部麻醉
- `NERVE_BLOCK` / 神经阻滞麻醉
- `NO_ANESTHESIA` / 无麻醉

#### 手术切口等级 `incisionGrade`

- `0`
- `I`
- `II`
- `III`

#### 切口愈合等级 `incisionHealingGrade`

- `甲`
- `乙`
- `丙`
- `其他`

#### 术后去向 `postoperativeDestination`

- `RETURN_WARD`
- `PACU`
- `ICU`
- `EICU`
- `DISCHARGED`
- `TRANSFER`
- `DEATH`

## 9. 字段校验与幂等建议

### 9.1 必填校验建议

- 所有接口至少必填：`eventId`、`traceId`、`eventTime`、`hospitalId`、`orgCode`、`sourceSystem`、`patientId`、`visitId`、`visitNo`、`encounterType`。
- 办理入院接口至少要求携带入院时间、入院科室、入院诊断。
- 手术确认接口至少要求携带手术单号、确认手术列表、主刀医生、手术室、计划开始时间、麻醉方式。
- 手术完成单接口至少要求携带手术单号、实际开始时间、实际结束时间、实施手术列表、术后诊断。
- 办理出院接口至少要求携带出院时间、出院科室、出院诊断、出院去向。

### 9.2 幂等建议

- 使用 `eventId` 作为业务幂等键。
- 若同一事件发生修正，建议重新生成 `eventId`，并保持 `visitId`、`surgeryNo` 等业务主键不变。
- 对手术确认、手术完成单场景，建议以 `hospitalId + orgCode + visitId + surgeryNo` 作为业务唯一索引。

### 9.3 安全建议

- 若后续接口需开放给医院外部系统直连，建议增加签名头：
  - `X-Access-Key`
  - `X-Timestamp`
  - `X-Nonce`
  - `X-Signature`
  - `X-Sign-Version`
- 手机号、身份证号等敏感信息应按医院安全规范传输和展示。

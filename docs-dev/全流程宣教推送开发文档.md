# 宣教智能体推送

## 涉及的接口
- 病历确诊接口 /api/b2b/qz/hp/diagnosis-event

## 开发计划
本次开发仅开发推送规则0~10

设计合适的表结构，用于配置及时推送规则、延时推送规则,要求：归纳推送规则
1. 即时推送
2. 延时推送 

推送规则与tag编码的映射关系在表中配置，程序获取到tag后的推送步骤现有代码已经实现

后续，扩充病种修改规则只用修改表中的数据，不再需要重复编码


推送需要记录，同一患者，PushTaskConstants的同一tag数据在本系统中只需要成功推送一次

新需求的PushTaskConstants的tag 不再硬编码到代码中，而是在表中配置（原PushTaskConstants逻辑不变）。

你可以酌情选择设计一张表或者多张表，综合考虑可维护性、可扩展性


## 说明
1. 诊断码匹配为任意字串匹配
2. 药品只按照名称子串匹配，不用支持药品编码
3. 只有确诊事件需要检验diagnosisCodeSystem=="ICD-10" 对于 diagnosisCodeSystem!="ICD-10" 的请求，日志记录并跳过

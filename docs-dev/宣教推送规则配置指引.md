# 宣教推送规则配置指引

本文用于后期运维配置宣教推送规则。当前规则由数据库表驱动，代码只识别固定的事件类型、触发类型、条件字段和匹配方式。

## 1. 配置范围

当前仅支持以下两个事件入口：

- 病历确诊事件：`/api/b2b/qz/hp/diagnosis-event`
- 处方开具事件：`/api/b2b/qz/hp/prescription`

当前不支持在数据库中新增任意接口字段。可配置字段以本文“条件配置”章节为准。

## 2. 相关表

### `qz_education_push_rule`

规则主表，用于配置规则编码、事件类型、即时/延时类型、推送 tag 和延时关系。

常用字段：

- `rule_code`：规则唯一编码，不可重复。建议使用业务可读编码，例如 `WY_QZ`、`WY_FCTX`。
- `rule_name`：规则名称，便于运维识别。
- `event_type`：事件类型。可选：`DIAGNOSIS_EVENT`、`PRESCRIPTION_EVENT`。
- `trigger_type`：触发类型。可选：`IMMEDIATE`、`DELAYED`。
- `tag`：推送给微信消息接口的 tag 编码。
- `previous_rule_code`：延时规则对应的前置即时规则编码。即时规则填 `NULL`。
- `delay_amount`：延时时长数值。即时规则填 `NULL`。
- `delay_unit`：延时单位。可选：`HOURS`、`DAYS`、`MONTHS`。即时规则填 `NULL`。
- `enabled`：是否启用。`1` 启用，`0` 停用。
- `sort_order`：同一事件类型下的匹配顺序，数值越小越先匹配。
- `remark`：备注。

### `qz_education_push_rule_condition`

规则条件表，用于配置某条即时规则的匹配条件。

常用字段：

- `rule_id`：对应 `qz_education_push_rule.id`。
- `field_name`：匹配字段。可选：`diagnosisCodeSystem`、`diagnosisCode`、`medicineName`。
- `match_type`：匹配方式。可选：`EQUALS_IGNORE_CASE`、`CONTAINS_IGNORE_CASE`。
- `match_value`：匹配值。
- `enabled`：是否启用。`1` 启用，`0` 停用。
- `sort_order`：条件排序，仅用于查看和稳定加载顺序。

### `wechat_push_success_record`

成功推送幂等表。系统成功推送后会自动写入。

- 唯一键：`patient_id + tag`。
- 同一患者同一 tag 只成功推送一次。
- 失败记录不会写入此表，因此失败不会阻止后续重试或再次触发。
- 运维一般不要手工删除该表数据；删除后可能导致同一患者同一 tag 再次推送。

## 3. 条件匹配规则

条件匹配采用：

- 同一 `field_name` 的多条条件按 OR 处理。
- 不同 `field_name` 之间按 AND 处理。

示例：糖尿病处方规则包含以下条件：

- `diagnosisCodeSystem = ICD-10`
- `diagnosisCode` 包含 `E10` 或 `E11` 或 `E14`
- `medicineName` 包含 `胰岛素` 或 `利拉鲁肽` 或 `司美格鲁肽` 或 `替尔泊肽`

最终含义是：

```text
diagnosisCodeSystem 等于 ICD-10
AND diagnosisCode 包含 E10/E11/E14 任意一个
AND medicineName 包含指定药品名任意一个
```

## 4. 支持的配置值

### 事件类型 `event_type`

- `DIAGNOSIS_EVENT`：病历确诊事件。
- `PRESCRIPTION_EVENT`：处方开具事件。

### 触发类型 `trigger_type`

- `IMMEDIATE`：即时规则。事件请求命中后立即推送。
- `DELAYED`：延时规则。由前置即时规则命中后创建延时任务。

### 条件字段 `field_name`

- `diagnosisCodeSystem`：诊断编码体系。
- `diagnosisCode`：诊断编码。
- `medicineName`：药品名称，来源于 `medicineItem[].medicineName`，同时兼容 `medicines` 字符串列表。

### 匹配方式 `match_type`

- `EQUALS_IGNORE_CASE`：忽略大小写完全相等。
- `CONTAINS_IGNORE_CASE`：忽略大小写子串包含。

诊断码和药品名通常使用 `CONTAINS_IGNORE_CASE`。

### 延时单位 `delay_unit`

- `HOURS`：小时。
- `DAYS`：天。
- `MONTHS`：月。

延时基准时间为前置即时规则在系统中判定为可推送的时间，使用 `Asia/Shanghai` 时区。

## 5. 新增即时规则

示例：新增一个确诊规则，诊断码包含 `K30` 时推送 `NEW_TAG`。

```sql
INSERT INTO qz_education_push_rule
    (rule_code, rule_name, event_type, trigger_type, tag, enabled, sort_order, remark)
VALUES
    ('NEW_QZ', '示例确诊宣教', 'DIAGNOSIS_EVENT', 'IMMEDIATE', 'NEW_TAG', 1, 100, '诊断码包含K30');

INSERT INTO qz_education_push_rule_condition
    (rule_id, field_name, match_type, match_value, sort_order)
SELECT id, 'diagnosisCodeSystem', 'EQUALS_IGNORE_CASE', 'ICD-10', 0
FROM qz_education_push_rule
WHERE rule_code = 'NEW_QZ';

INSERT INTO qz_education_push_rule_condition
    (rule_id, field_name, match_type, match_value, sort_order)
SELECT id, 'diagnosisCode', 'CONTAINS_IGNORE_CASE', 'K30', 1
FROM qz_education_push_rule
WHERE rule_code = 'NEW_QZ';
```

配置后，请使用对应事件接口发送测试请求，确认推送日志和成功记录符合预期。

## 6. 新增延时规则

延时规则必须挂在某个即时规则后面，通过 `previous_rule_code` 关联。

示例：`NEW_QZ` 命中后 7 天推送 `NEW_FOLLOW_TAG`。

```sql
INSERT INTO qz_education_push_rule
    (rule_code, rule_name, event_type, trigger_type, tag, previous_rule_code, delay_amount, delay_unit, enabled, sort_order, remark)
VALUES
    ('NEW_FOLLOW', '示例7天后提醒', 'DIAGNOSIS_EVENT', 'DELAYED', 'NEW_FOLLOW_TAG', 'NEW_QZ', 7, 'DAYS', 1, 101, 'NEW_QZ命中7天后');
```

延时规则不需要配置条件。系统只会按 `previous_rule_code` 查找启用的延时规则。

前置即时规则一旦判定命中，会立即创建延时任务，不依赖微信实际推送是否成功。

## 7. 修改已有规则

### 停用规则

```sql
UPDATE qz_education_push_rule
SET enabled = 0
WHERE rule_code = 'WY_QZ';
```

停用即时规则后，该即时规则不会再触发，也不会再创建挂在它下面的延时任务。

### 修改 tag

```sql
UPDATE qz_education_push_rule
SET tag = 'NEW_TAG'
WHERE rule_code = 'WY_QZ';
```

注意：成功幂等按 `patient_id + tag` 判断。修改 tag 后，对于同一患者，新 tag 会被视为新的推送内容，可能再次推送。

### 修改诊断码匹配值

```sql
UPDATE qz_education_push_rule_condition c
JOIN qz_education_push_rule r ON r.id = c.rule_id
SET c.match_value = 'K29'
WHERE r.rule_code = 'WY_QZ'
  AND c.field_name = 'diagnosisCode'
  AND c.match_value = 'K29.0';
```

### 增加一个 OR 条件

示例：给 `WY_QZ` 增加 `K30` 诊断码。

```sql
INSERT INTO qz_education_push_rule_condition
    (rule_id, field_name, match_type, match_value, sort_order)
SELECT id, 'diagnosisCode', 'CONTAINS_IGNORE_CASE', 'K30', 2
FROM qz_education_push_rule
WHERE rule_code = 'WY_QZ';
```

## 9. 运维检查 SQL

查看启用规则：

```sql
SELECT rule_code, rule_name, event_type, trigger_type, tag, previous_rule_code,
       delay_amount, delay_unit, enabled, sort_order
FROM qz_education_push_rule
WHERE enabled = 1
ORDER BY event_type, trigger_type, sort_order;
```

查看某条规则的条件：

```sql
SELECT r.rule_code, c.field_name, c.match_type, c.match_value, c.enabled, c.sort_order
FROM qz_education_push_rule_condition c
JOIN qz_education_push_rule r ON r.id = c.rule_id
WHERE r.rule_code = 'TNB_CF'
ORDER BY c.field_name, c.sort_order;
```

查看某患者某 tag 是否已成功推送：

```sql
SELECT *
FROM wechat_push_success_record
WHERE patient_id = '患者ID'
  AND tag = 'TNB_CF';
```

查看待执行或失败的延时任务：

```sql
SELECT id, task_type, patient_id, tag, source_no, trigger_time, next_retry_time,
       retry_count, max_retry_count, status, enqueue_status, last_error_message
FROM wechat_push_task
WHERE status IN ('PENDING', 'FAILED')
ORDER BY next_retry_time
LIMIT 100;
```

查看推送日志：

```sql
SELECT id, patient_id, tag, push_status, wechat_api_code, wechat_api_message,
       error_message, create_time
FROM wechat_push_log
WHERE patient_id = '患者ID'
ORDER BY id DESC
LIMIT 50;
```

## 10. 注意事项

1. `patientId` 必填，接口层校验不通过会返回失败。
2. 确诊和处方事件都要求 `diagnosisCodeSystem = ICD-10`，否则系统只记录跳过原因并返回成功。
3. `diagnosisCode` 为空会跳过，不触发规则。
4. 处方事件中药品名为空会跳过，不触发规则。
5. 延时任务创建后，会进入 `wechat_push_task`，由定时任务和 Redis ZSet 调度执行。
6. 已成功推送过的 `patient_id + tag` 会被跳过，不会再次真实推送。
7. 修改规则配置建议先在测试环境验证，再在生产环境执行。
8. 已经执行过的 Flyway 迁移脚本不要直接修改；生产变更建议通过新迁移脚本或受控 SQL 发布。

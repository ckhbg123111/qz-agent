# 宣教智能体消息接口测试请求示例

## 1. 文档说明

本文档用于提供宣教智能体消息接口的手工联调请求示例，方便 HIS 通过 Postman、Apifox、SOAP UI 或自有 WebService 客户端直接联调。

说明如下：

- 当前接口已改为 `SOAP 1.1 + 单一方法 receiveMessage`
- 所有业务消息统一通过一个服务地址发送
- `messageXml` 节点中承载原业务 XML 报文
- 本文档只保留当前 HIS 明确可发送、且当前系统实际支持联调的消息类型
- 正式联调仍以 `docs/宣教智能体消息接口对接文档.md` 为准

## 2. 当前联调范围

### 2.1 当前可联调的消息类型

| 序号 | 接口名称 | 请求事件类型 | 说明 |
| --- | --- | --- | --- |
| 1 | 患者入出转推送(门诊) | `ADT_A01_MZ` | 当前仅接受 `EventInfo.EventTypeCode=REG` |
| 2 | 检查申请单推送（开立、作废） | `ORM^O01^ORM_O01` | 统一通过 SOAP 方法发送 |
| 3 | 医技状态回传（检查） | `ORM^O01^JCZTGB_XML` | 统一通过 SOAP 方法发送 |
| 4 | 检查报告发布/危急值回传 | `ORU^R01^JCBGHC_XML` | 统一通过 SOAP 方法发送 |
| 5 | 药品治疗医嘱信息推送 | `OMP^O09^OMP_O09` | 统一通过 SOAP 方法发送 |

### 2.2 当前不在本示例中的类型

- `检查预约推送 SIU^S12^SIU_S12`
  说明：HIS 已明确反馈该消息当前暂未启用，因此本示例文档不再提供联调请求。

- `门诊检验相关推送`
  说明：HIS 已明确反馈门诊检验当前不走推送，而是通过查询类接口获取，因此本示例文档不再提供：
  - `OML_O21_OML_O21`
  - `OML^O21^JYZTGB_XML`
  - `OUL^R21^JYBGHC_XML`

## 3. 通用调用方式

### 3.1 服务地址

当前内网服务器尚未申请，以下地址均使用占位符表示：

```text
SOAP 地址:
http://<host>:<port>/api/b2b/sdhp/ws/health-education-agent-service

WSDL 地址:
http://<host>:<port>/api/b2b/sdhp/wsdl/health-education-agent-message.wsdl
```

### 3.2 SOAP 服务定义

| 项目 | 值 |
| --- | --- |
| Service Name | `HealthEducationAgentMessageService` |
| Port Name | `HealthEducationAgentMessagePort` |
| Operation | `receiveMessage` |
| SOAPAction | `http://aiqikang.com/sdhp/ws/receiveMessage` |
| Namespace | `http://aiqikang.com/sdhp/ws` |
| 参数名 | `messageXml` |
| 返回值 | `return` |

### 3.3 请求方式

- HTTP 方法：`POST`
- 请求头：`Content-Type: text/xml;charset=UTF-8`
- SOAPAction：`http://aiqikang.com/sdhp/ws/receiveMessage`
- 鉴权：当前版本无需携带登录鉴权信息

### 3.4 通用 SOAP 包装格式

所有业务请求统一采用以下 SOAP 外层：

```xml
<soapenv:Envelope xmlns:soapenv="http://schemas.xmlsoap.org/soap/envelope/"
                  xmlns:sdhp="http://aiqikang.com/sdhp/ws">
  <soapenv:Header/>
  <soapenv:Body>
    <sdhp:receiveMessage>
      <sdhp:messageXml><![CDATA[
        这里放具体业务 XML
      ]]></sdhp:messageXml>
    </sdhp:receiveMessage>
  </soapenv:Body>
</soapenv:Envelope>
```

## 5. 使用建议

- 每次调用时建议替换 `MsgId`，保证唯一
- `MessageHeader.EventType` 必须与接口定义完全一致
- 返回虽然通常是 HTTP `200`，但仍需检查 SOAP `return` 节点中的业务 ACK
- 业务 ACK 中 `Result.Code=CA` 表示成功，`Result.Code=CE` 表示失败
- 如需联调门诊检验场景，请不要使用本文件中的推送示例，而应按 `docs/宣教智能体消息接口对接文档.md` 中“门诊检验查询说明”改为查询类接口联调

## 1. 文档说明

本文档用于说明当前项目已落地的宣教智能体消息接口接入方式、请求路径、报文结构、ACK 返回规则和联调注意事项，便于 HIS、LIS、RIS 或第三方系统按当前系统实现进行对接。

说明如下：

- 本文档以当前代码实现和已部署测试环境为准
- 当前实现为消息接收接口，仅负责接收 XML 报文、做基础校验并返回 ACK
- 当前文档重点回答“调哪个地址、传什么结构、返回什么内容、哪些场景会失败”

## 3. 公共调用规范

### 3.1 公共请求结构

所有接口统一使用如下请求结构：

```xml
<Request>
  <MessageHeader>
    <Sender>HIS</Sender>
    <Receiver>ZJ_AGENT</Receiver>
    <SendTime>20260401120000</SendTime>
    <EventType>ADT_A01_MZ</EventType>
    <MsgId>TEST-20260401120000</MsgId>
  </MessageHeader>
  <MessageBody>
    <!-- 具体业务节点 -->
  </MessageBody>
</Request>
```

### 3.2 公共请求头字段

| 节点 | 字段 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| `MessageHeader` | `Sender` | 否 | 发送方系统标识，建议必传，ACK 会回填到 `Receiver` |
| `MessageHeader` | `Receiver` | 否 | 接收方系统标识，建议传 `ZJ_AGENT` |
| `MessageHeader` | `SendTime` | 否 | 发送时间，建议格式 `yyyyMMddHHmmss` |
| `MessageHeader` | `EventType` | 是 | 消息事件类型，必须与接口定义完全一致 |
| `MessageHeader` | `MsgId` | 是 | 消息唯一标识，同一请求应保证唯一 |

### 3.3 公共响应结构

所有接口统一返回 ACK 报文：

```xml
<Response>
  <MessageHeader>
    <Sender>ZJ_AGENT</Sender>
    <Receiver>HIS</Receiver>
    <SendTime>20260401124023</SendTime>
    <EventType>ACK_ADT_A01_MZ</EventType>
    <MsgId>DOC-CHECK-0001</MsgId>
  </MessageHeader>
  <MessageBody>
    <Result>
      <Code>CA</Code>
    </Result>
  </MessageBody>
</Response>
```

说明：

- 成功时 `Result.Desc` 通常为空，实际序列化结果会省略该节点
- 失败时会返回 `Result.Desc`，写入明确的错误原因

### 3.4 ACK 规则

| 字段 | 说明 |
| --- | --- |
| `Result.Code=CA` | 处理成功 |
| `Result.Code=CE` | 处理失败 |
| `Result.Desc` | 失败原因说明，成功时通常不返回该节点 |

响应头生成规则：

- `Sender` 固定返回 `ZJ_AGENT`
- `Receiver` 回填请求头中的 `Sender`
- `MsgId` 回填请求头中的 `MsgId`
- `SendTime` 为服务端当前时间，格式 `yyyyMMddHHmmss`
- `EventType` 为各接口对应的 ACK 事件类型

### 3.5 当前统一校验规则

除业务特殊说明外，所有接口都会做以下基础校验：

1. 请求报文不能为空
2. `MessageHeader` 不能为空
3. `MessageBody` 不能为空
4. `MessageHeader.EventType` 不能为空
5. `MessageHeader.EventType` 必须与接口定义一致
6. `MessageHeader.MsgId` 不能为空

校验失败时：

- HTTP 状态码仍返回 `200`
- ACK 中 `Result.Code=CE`
- 具体失败原因写入 `Result.Desc`

## 5. 各接口说明

### 5.1 患者入出转推送(门诊)

- 协议章节：`患者入出转推送(门诊) ADT_A01_ADT_A01（MZ）`
- 请求路径：`/api/b2b/sdhp/patient/adt-a01-mz`
- 请求事件类型：`ADT_A01_MZ`
- 响应事件类型：`ACK_ADT_A01_MZ`

`MessageBody` 结构：

```xml
<MessageBody>
  <EventInfo />
  <PatientInfo />
  <PatientVisitInfo />
  <ChargeInfo />
  <OutpDurationInfo />
</MessageBody>
```

主要业务节点：

| 节点 | 说明 |
| --- | --- |
| `EventInfo` | 事件信息，包含 `EventTypeCode`、记录时间、操作人等 |
| `PatientInfo` | 患者基础信息 |
| `PatientVisitInfo` | 门诊就诊信息 |
| `ChargeInfo` | 费用类别信息 |
| `OutpDurationInfo` | 门诊日期和时间段信息 |

特殊校验：

- `EventInfo.EventTypeCode` 不能为空
- 当前仅处理 `EventInfo.EventTypeCode=REG`
- 当 `EventTypeCode` 为其他值时，返回 `CE`，错误信息为“当前接口仅处理挂号成功事件REG”

## 7. 常见失败原因

| 场景 | 返回说明 |
| --- | --- |
| 请求报文为空 | `请求报文不能为空` |
| `MessageHeader` 为空 | `MessageHeader不能为空` |
| `MessageBody` 为空 | `MessageBody不能为空` |
| `EventType` 为空 | `EventType不能为空` |
| `EventType` 不匹配 | `EventType不匹配，期望值为{接口事件类型}` |
| `MsgId` 为空 | `MsgId不能为空` |
| 门诊患者接口未传 `EventInfo.EventTypeCode` | `EventInfo.EventTypeCode不能为空` |
| 门诊患者接口 `EventInfo.EventTypeCode` 非 `REG` | `当前接口仅处理挂号成功事件REG` |

## 8. 联调建议

1. 先按本文档接口清单确认每个业务场景对应的请求路径和 `EventType`
2. 报文根节点、头节点和体节点名称必须严格匹配，区分大小写
3. 列表节点建议严格按照原始协议文档中的 XML 结构组织
4. 如果对字段明细、枚举值或示例值有疑问，可结合 `docs/单病种消息接口测试请求示例.md` 与 `docs/单病种分诊系统V1.0.md` 一起确认
5. 当前系统重点校验公共头和部分关键业务字段，不代表未校验字段可以随意传值，正式联调仍建议按原始协议完整报送
6. 对接方验收时不要只看 HTTP 状态码，必须同步校验 ACK 中的 `Result.Code`

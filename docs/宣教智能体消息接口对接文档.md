## 1. 文档说明

本文档用于说明宣教智能体当前对 HIS 的统一 SOAP 接入方式。

本次改造后，不再按不同业务消息暴露多个 HTTP XML 地址，而是改为：

- 只有一个服务地址
- 只有一个服务类
- 只有一个方法 `receiveMessage`
- 所有业务消息统一通过 SOAP 请求发送
- 服务端根据业务 XML 中 `MessageHeader.EventType` 自动分发处理

说明如下：

- SOAP 外层协议改为统一入口
- SOAP 方法参数只接收一个字符串参数：`messageXml`
- `messageXml` 内部仍沿用原有业务 XML 结构
- 返回值为字符串类型 ACK XML，由 SOAP 响应统一承载

## 2. 接入总览

## 3. SOAP 报文结构

### 3.1 SOAP 请求样例

```xml
<soapenv:Envelope xmlns:soapenv="http://schemas.xmlsoap.org/soap/envelope/"
                  xmlns:sdhp="http://aiqikang.com/sdhp/ws">
  <soapenv:Header/>
  <soapenv:Body>
    <sdhp:receiveMessage>
      <sdhp:messageXml><![CDATA[
<Request>
  <MessageHeader>
    <Sender>HIS</Sender>
    <Receiver>ZJ_AGENT</Receiver>
    <SendTime>20260401120000</SendTime>
    <EventType>ADT_A01_MZ</EventType>
    <MsgId>TEST-20260401120000</MsgId>
  </MessageHeader>
  <MessageBody>
    <EventInfo>
      <EventTypeCode>REG</EventTypeCode>
    </EventInfo>
  </MessageBody>
</Request>
      ]]></sdhp:messageXml>
    </sdhp:receiveMessage>
  </soapenv:Body>
</soapenv:Envelope>
```

说明：

- `messageXml` 节点内容为原业务 XML 字符串
- 可使用 CDATA，也可使用标准 XML 转义方式传输
- 当前服务只要求一个方法参数，不再按业务配置多个 URL

### 3.2 SOAP 响应样例

```xml
<soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">
  <soap:Body>
    <sdhp:receiveMessageResponse xmlns:sdhp="http://aiqikang.com/sdhp/ws">
      <sdhp:return><![CDATA[
<Response>
  <MessageHeader>
    <Sender>ZJ_AGENT</Sender>
    <Receiver>HIS</Receiver>
    <SendTime>20260401124023</SendTime>
    <EventType>ACK_ADT_A01_MZ</EventType>
    <MsgId>TEST-20260401120000</MsgId>
  </MessageHeader>
  <MessageBody>
    <Result>
      <Code>CA</Code>
    </Result>
  </MessageBody>
</Response>
      ]]></sdhp:return>
    </sdhp:receiveMessageResponse>
  </soap:Body>
</soap:Envelope>
```

说明：

- SOAP 返回值中的 `return` 节点为 ACK XML 字符串
- HIS 需要从 `return` 中取出业务 ACK 内容

## 4. 业务 XML 公共结构

所有消息统一使用如下业务 XML 结构，作为 `messageXml` 的内容传入。

### 4.1 公共请求结构

```xml
<Request>
  <MessageHeader>
    <Sender>HIS</Sender>
    <Receiver>ZJ_AGENT</Receiver>
    <SendTime>20260401120000</SendTime>
    <EventType>ADT_A01_MZ</EventType>
    <MsgId>TEST-20260401120000</MsgId>
  </MessageHeader>
  <MessageBody>
    <!-- 具体业务节点 -->
  </MessageBody>
</Request>
```

### 4.2 公共请求头字段

| 节点 | 字段 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| `MessageHeader` | `Sender` | 否 | 发送方系统标识，建议必传 |
| `MessageHeader` | `Receiver` | 否 | 接收方系统标识，建议传 `ZJ_AGENT` |
| `MessageHeader` | `SendTime` | 否 | 发送时间，建议格式 `yyyyMMddHHmmss` |
| `MessageHeader` | `EventType` | 是 | 消息事件类型，必须与定义完全一致 |
| `MessageHeader` | `MsgId` | 是 | 消息唯一标识，同一请求应保证唯一 |

### 4.3 公共 ACK 结构

```xml
<Response>
  <MessageHeader>
    <Sender>ZJ_AGENT</Sender>
    <Receiver>HIS</Receiver>
    <SendTime>20260401124023</SendTime>
    <EventType>ACK_ADT_A01_MZ</EventType>
    <MsgId>TEST-20260401120000</MsgId>
  </MessageHeader>
  <MessageBody>
    <Result>
      <Code>CA</Code>
    </Result>
  </MessageBody>
</Response>
```

### 4.4 ACK 规则

| 字段 | 说明 |
| --- | --- |
| `Result.Code=CA` | 处理成功 |
| `Result.Code=CE` | 处理失败 |
| `Result.Desc` | 失败原因说明，成功时通常不返回 |

响应头生成规则：

- `Sender` 固定返回 `ZJ_AGENT`
- `Receiver` 回填请求头中的 `Sender`
- `MsgId` 回填请求头中的 `MsgId`
- `SendTime` 为服务端当前时间，格式 `yyyyMMddHHmmss`
- `EventType` 为各业务消息对应的 ACK 类型

## 6. 当前校验规则

除业务特殊说明外，所有消息都会做以下基础校验：

1. 请求报文不能为空
2. `MessageHeader` 不能为空
3. `MessageBody` 不能为空
4. `MessageHeader.EventType` 不能为空
5. `MessageHeader.EventType` 必须与消息定义一致
6. `MessageHeader.MsgId` 不能为空

校验失败时：

- 仍返回 SOAP 响应
- `return` 中 ACK 的 `Result.Code=CE`
- `Result.Desc` 写入明确失败原因

### 6.1 患者入出转推送(门诊) 特殊校验

- `EventInfo.EventTypeCode` 不能为空
- 当前仅处理 `EventInfo.EventTypeCode=REG`
- 其他值返回 `CE`，错误说明为“当前接口仅处理挂号成功事件REG”

### 6.2 未支持事件

若 `EventType` 不在当前支持范围内，返回：

- `ACK.EventType=ACK`
- `Result.Code=CE`
- `Result.Desc=暂不支持的EventType: xxx`

## 7. 业务体说明

SOAP 统一入口只改变外层接入方式，不改变业务 XML 主体结构。

也就是说：

- 原来各业务消息对应的 `MessageBody` 节点结构继续保留
- HIS 无需再按不同 URL 调不同接口
- HIS 只需将原业务 XML 放入 `messageXml` 参数中统一发送

如需查看各业务体字段明细，可沿用原项目约定的业务 XML 结构定义。

## 10. 门诊检验查询说明

### 10.1 场景说明

根据 HIS 反馈，当前门诊检验不会主动向宣教智能体产生推送消息。

因此：

- 门诊检验场景不依赖 `OML_O21_OML_O21` 推送触发
- 系统改为主动调用 HIS/LIS 的查询类接口获取检验申请数据
- 当前已实现的是“定时查询 + 日志记录 + 落库保存”
- 当前阶段仅保存查询结果，不直接触发后续宣教业务

### 10.2 使用的查询接口

本系统当前使用 [C:/Users/Administrator/Desktop/qz-agent/docs/单病种分诊系统V1.0.md](C:/Users/Administrator/Desktop/qz-agent/docs/单病种分诊系统V1.0.md) 中的检验申请查询接口：

- 接口名称：`检验申请查询 QBP_Z06_QBP_Q11`
- 查询标记：`Z0601`
- 请求事件类型：`QBP^Q11^CXJYSQ_XML`
- 应答事件类型：`ACK_QBP^Q11^CXJYSQ_XML`

该接口适用于按患者 + 执行科室 + 时间窗口查询门诊检验申请。

### 10.3 当前查询策略

系统通过定时任务主动轮询，策略如下：

- 调度开关：`lab.query.enabled`
- 调度周期：`lab.query.fixed-delay-ms`
- 首次查询回看分钟数：`lab.query.initial-lookback-minutes`
- 查询水位按“上次成功结束时间”保存
- 每次查询使用 `Z0601` 按时间窗拉取数据
- 当前只查询配置中的患者列表：`lab.query.patient-ids`

说明：

- 文档中的 `QBP_Z06` 门诊查询要求传入 `PatientId`
- 因此当前版本需要通过配置提供待轮询的患者 ID 列表
- 若未配置 `patient-ids`，定时任务不会执行实际查询

### 10.4 当前保存内容

每次定时查询会保存以下内容：

- 查询任务水位：上次成功开始时间、结束时间、最后状态、最后错误信息
- 查询日志：患者 ID、查询时间窗、请求 XML、响应 XML、结果码、结果说明、返回 `OrderInfo` 数量

### 10.5 范围说明

本次实现只覆盖“检验申请查询”，不包含以下能力：

- 检验报告查询
- 检验结果查询
- 查询结果自动转换为宣教业务消息
- 查询结果自动触发后续宣教流程

如果后续 HIS/LIS 提供新的检验结果或报告查询接口，可在现有查询框架上继续扩展。

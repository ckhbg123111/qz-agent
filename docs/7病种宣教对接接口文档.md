## 2. 接口公共约定

### 2.1 请求约定

- 请求方式：`POST`
- 请求头：`Content-Type: application/json`
- 字符编码：`UTF-8`
- 时间字段建议使用 `ISO-8601` 格式，例如 `2026-04-22T09:18:00+08:00`
- 诊断编码优先使用 `ICD-10`，手术编码优先使用 `ICD-9-CM3` 或院内手术编码，检验项目编码优先使用院内 `LIS` 编码

### 2.2 返回约定

- `病历确诊接口`、`检验单开具接口`、4 个手术接口成功时返回 `Result<Boolean>`。
- `处方开具接口` 成功时返回 `Result<QzHpLinkVO>`，其中 `data.link` 为落地页链接，当前控制器成功时可能返回空字符串。

`Result<Boolean>` 成功返回示例：

```json
{
  "code": 200,
  "message": "success",
  "data": true
}
```

## 3. 病历确诊接口

- 接口名称：病历确诊接口
- 接口路径：`/api/b2b/qz/hp/diagnosis-event`
- 适用场景：胃炎、消化性溃疡、炎症性肠病、糖尿病确诊事件

### 3.1 请求头

| 名称 | 值 |
| --- | --- |
| Content-Type | `application/json` |

### 3.2 请求参数

| 字段名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| patientId | String | 是 | 患者 ID |
| department | String | 是 | 科室枚举，推荐传 `GASTROENTEROLOGY` 或 `ENDOCRINOLOGY` |
| diseaseType | Enum | 是 | 病种枚举，见下文 3.3 |
| patientName | String | 否 | 患者姓名 |
| gender | String | 否 | 患者性别，示例：`男`、`女`、`未知` |
| age | Integer | 否 | 患者年龄 |
| diagnosisCode | String | 否 | 主诊断编码，优先传 `ICD-10` |
| diagnosisCodeSystem | String | 否 | 诊断编码体系，默认 `ICD-10` |
| diagnosis | String | 否 | 主诊断名称 |
| remark | String | 否 | 备注 |
| date | String | 否 | 诊断日期，支持 `ISO-8601` 或 `yyyy-MM-dd` |
| doctor | String | 否 | 医生姓名 |

### 3.3 病种枚举

| 枚举值 | 中文说明 | 推荐场景 |
| --- | --- | --- |
| GASTRITIS | 胃炎 | 胃炎相关诊断 |
| PEPTIC_ULCER | 消化性溃疡 | 消化性溃疡、十二指肠溃疡、胃溃疡 |
| INFLAMMATORY_BOWEL_DISEASE | 炎症性肠病 | 溃疡性结肠炎、克罗恩病、炎症性肠病 |
| DIABETES_MELLITUS | 糖尿病 | 糖尿病相关诊断 |

### 3.4 请求示例

```json
{
  "patientId": "P202604160001",
  "department": "GASTROENTEROLOGY",
  "diseaseType": "GASTRITIS",
  "patientName": "张三",
  "gender": "男",
  "age": 36,
  "diagnosisCode": "K29.50",
  "diagnosisCodeSystem": "ICD-10",
  "diagnosis": "慢性胃炎",
  "remark": "门诊复诊",
  "date": "2026-04-16",
  "doctor": "李医生"
}
```

### 3.5 返回参数

| 字段名 | 类型 | 说明 |
| --- | --- | --- |
| code | Integer | 响应码 |
| message | String | 响应说明 |
| data | Boolean | 处理结果 |

### 3.6 返回示例

```json
{
  "code": 200,
  "message": "success",
  "data": true
}
```

### 3.7 业务说明

- 胃炎、消化性溃疡、炎症性肠病、糖尿病确诊事件均通过本接口接收。
- 建议同时传递 `diagnosisCode` 与 `diagnosis`，便于平台按编码和诊断名称双重识别。
- 糖尿病场景建议 `department` 传 `ENDOCRINOLOGY`；消化系统疾病场景建议传 `GASTROENTEROLOGY`。

## 5. 处方开具接口

| diagnosisCode | String | 否 | 主诊断编码，优先传 `ICD-10`，糖尿病示例 `E14.90` |
| diagnosisCodeSystem | String | 否 | 诊断编码体系，默认 `ICD-10` |
| diagnosis | String | 否 | 主诊断名称 |
| medicineItem | Array<Object> | 否 | 推荐使用的药品对象列表，子结构见下文 5.3 |
| medicines | Array<String> / Array<Object> / Object | 否 | 兼容字段。可传药品名称数组，也可传对象或对象数组，系统会自动解析 |

| department | String | 否 | 科室名称 |

| pharmacist | String | 否 | 审核药师 |

### 5.3 `medicineItem` 子结构

| 字段名 | 类型 | 必填 | 说明 |

| specification | String | 否 | 规格 |

| dosageUnit | String | 否 | 剂量单位，如 `IU`、`mg`、`ml` |

| route | String | 否 | 给药途径，如 `SC`、`IH`、`PO` |

### 5.5 返回参数

| 字段名 | 类型 | 说明 |
| --- | --- | --- |
| code | Integer | 响应码 |
| message | String | 响应说明 |
| data | Object | 返回对象 |
| data.link | String | 落地页链接，当前控制器成功时可能为空字符串 |

### 5.6 返回示例

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "link": ""

```

### 5.7 业务说明

- 对糖尿病场景，建议在 `medicineItem` 或 `medicines` 中传递胰岛素、利拉鲁肽、司美格鲁肽、替尔泊肽等药品信息。
- 推荐药品编码示例：胰岛素 `DRUG_INSULIN_001`、利拉鲁肽 `DRUG_LIRAGLUTIDE_001`、司美格鲁肽 `DRUG_SEMAGLUTIDE_001`、替尔泊肽 `DRUG_TIRZEPATIDE_001`。
- 若 `therapy` 中包含“二联”或“2 联”，平台会按二联治疗文案进行内部标记。
- 当前控制器成功后返回 `data.link` 字段，但示例实现可能返回空字符串，调用方应按返回结构解析。

## 7. 办理入院接口

- 适用场景：肾穿刺手术住院办理入院后推送

### 7.1 请求头

| 名称 | 值 |

- 肾穿刺和屈光手术均通过本接口接收术后完成事件，平台再根据手术编码、手术名称和完成时间触发后续宣教。
